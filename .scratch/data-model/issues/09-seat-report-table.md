# 座席レポのテーブル

Type: grilling
Status: open
Blocked by: 07, 08

## Question

このマップの中心。座席レポのテーブルを設計してマイグレーションにする。
- 4 軸評価の持ち方：今のように列で持つか（`visibility` など 4 列）、軸ごとの行で持つか。評価の範囲（1〜5 か、未評価を許すか）。軸ごとのコメント。
- 座席番号：今のように自由入力の 1 つの文字列か、構造化するか（階・ブロック・列・番など）。会場によって座席の形式が違う点をどう扱うか。
- 参戦日：任意の日付。期間の絞り込みを投稿日から参戦日に変えるか。
- アーティストの参照：必須か任意か。投稿時に新しいアーティストを追加する流れ。
- 匿名投稿：匿名ユーザーの投稿と本登録ユーザーの投稿を同じテーブルで持つ（`auth.users` の id で区別する）前提で、列に違いが出るか。
