# 座席レポ画像は投稿時に Go の Lambda で変換し、元画像は残さない

座席レポに付ける画像は、ブラウザから S3 に presigned POST で直接アップロードする。アップロードを S3 イベントで受けた Go の Lambda が、EXIF を取り除いた決まったサイズの画像を生成する。生成に成功したら元画像はすぐに削除し、変換後の画像を非公開の S3 から CloudFront（OAC）経由で配信する。座席から撮った写真には撮影場所（自宅周辺など）の位置情報が含まれうるため、位置情報を含む元データは必要以上に持たない。また、変換を投稿時の 1 回にすることで、閲覧数が増えても費用が増えない。

## Considered Options

- **Vercel の `<Image />` で表示時に変換する**：実装は最も楽だが、Hobby プランは月 5,000 変換が上限で、超えると新しい画像が表示されなくなる。また、Vercel が取得できるよう元画像を公開 URL に置く必要があり、EXIF の位置情報が誰でも読める状態になる。
- **AWS 公式の画像変換ソリューション**：認証のない公開エンドポイントができ、費用が読めない項目もある。
- **Lambda@Edge**：Go で書けず、無料枠もない。
- **presigned PUT**：ファイルサイズの上限を S3 側で強制できない。
- **元画像を非公開で保管し続ける**：あとから別のサイズを作り直せるが、位置情報を持ち続けることになる。新しいサイズは、変換後でいちばん大きい画像から作る。

## Consequences

- 投稿フォームの途中でアップロードしてプレビューを見せるため、画像はいったん一時置き場に置き、座席レポの投稿時に紐付ける。紐付かなかった画像は S3 のライフサイクルルールで 1 日後に削除する。
- 投稿してから変換済みの画像ができるまでに時間差があるので、画面に「処理中」の状態が必要になる。
- cgo を使わない WebP エンコーダーの速度とメモリは実測が必要。遅すぎる場合は、Go の標準ライブラリによる JPEG の再エンコードに切り替える（EXIF の除去はどちらでもできる）。
