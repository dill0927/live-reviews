# 会場とアイドルのマスタは seed ではなくマイグレーションで入れる

会場とアイドルのマスタのデータは、`supabase/seed.sql` ではなく `supabase/migrations/` の `insert` で入れる。会場を追加したり修正したりするときも、新しいマイグレーションを足す。決め手は、ローカル・dev・prod に同じデータが同じ順番で入ること。マスタを管理する画面は作らず、運営が SQL で入れると決めたので、マスタは「スキーマの一部」として履歴で管理するのがいちばん単純になる。`seed.sql` は、ローカル専用のダミーデータ（テスト用のユーザーや座席レポ）の置き場にする。

## Considered Options

- **`seed.sql` に書き、dev と prod には `supabase db push --include-seed` で流す**：Supabase の慣習どおり。ただし、2 回目以降の push で seed がどう扱われるか（変更した seed が流れ直すか）を確かめる必要があり、ローカル専用のダミーデータとも同じファイルに混ざる。
- **CSV を読み込むスクリプト**：データは見やすいが、CLI の外に仕組みが増える。

## Consequences

- 会場の追加・修正は、`update` や `insert` のマイグレーションを書いて PR にする。履歴が残るので、いつ何を直したかを追える。
- マスタの ID はマイグレーションで固定される。現行の re-sekirepo の ID を引き継いでいる。
- `make db-reset` のたびにマスタも入るので、テストはマスタがある前提で書ける。
