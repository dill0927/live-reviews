# 読み取りの要件（検索・集計）とインデックス

Type: grilling
Status: resolved
Blocked by: 09

## Question

座席レポ・会場・アイドルをどう探し、どう集計するかを決め、必要なインデックス・拡張機能・ビューをマイグレーションにする。
- 座席の検索：座席番号は自由入力（「座席レポのテーブル」で決定）なので、部分一致をどう速くするか。
- コメントのキーワード検索：日本語の部分一致をどう速くするか（`pg_trgm` など）。そもそも機能として要るか。
- 期間の絞り込み：今は投稿日（`created_at`）。参戦日（`attended_on`）に変えるか。
- 公演名での絞り込み。
- 会場ごとの 4 軸評価の平均：今はブラウザで計算している。毎回 SQL で集計するか、ビューや集計用のテーブルにするか。
- 会場とアイドルの検索：今は `search_venues` という RPC。読み仮名の `kana` を使うか、`pg_trgm` を入れるか。

補足：外部キーの 3 つのインデックス（`venue_id`・`idol_id`・`user_id`）は「座席レポのテーブル」で付けた。拡張機能は使うチケットで入れる（「スキーマ全体の規約」）。見せ方（検索フォームの形など）は UI/UX のマップに回し、ここでは DB で何を速く引けるようにするかまでを決める。

## Resolution（2026-10-26）

### 決めたこと
- **部分一致用のインデックスは張らず、拡張機能（`pg_trgm`）も入れない**。会場ごとの絞り込みは今ある外部キーのインデックス（`venue_id` など）で行い、残りはシーケンシャルスキャンで探す。理由は 2 つ。座席番号の検索は「A1」「北」のような 2 文字以下の語が多く、`pg_trgm` の GIN インデックスは 3 文字に満たない検索語では使われない。また、1 会場あたり数百件なら、全件を比べても数ミリ秒で終わる。遅くなったら `EXPLAIN` で確かめてから足す（後から足せるので ADR は書かない）。
- **座席の検索**：`seat_number` の部分一致。
- **期間の絞り込みは参戦日（`attended_on`）に変える**。演出や座席の配置は公演の時期で変わるため。一覧の並びは新着順（`created_at`）のまま。
- **コメントのキーワード検索は持つ**。対象は 4 つのコメント列だけで、部分一致。座席番号と公演名にはそれぞれ専用の絞り込みがあるので含めない（キーワード検索は「体験」で探すもの）。
- **公演名**：自由入力なので部分一致で絞り込む。
- **会場ごとの平均は、見やすさ・周辺施設・アクセスの 3 軸と件数**。ファンサは公演の演出とアイドルで大きく変わり、会場単位の平均には意味がないので出さない。アイドルや公演名で絞ったときの平均か、個々のレポで見せる。集計は毎回 SQL で行い、ビューも集計用のテーブルも作らない（集計用のテーブルは値がずれる元になる）。
- **会場とアイドルの検索**：Go から SQL で `name` と `kana` を部分一致で探す。表記の揺れ（カタカナ→ひらがな、全角・半角）は Go の側でそろえる。今の `search_venues` のような DB の関数（RPC）は作らない（Data API を塞ぐので呼べなくなる。ロジックを Go に集めたほうがテストしやすい）。

### 確かめたこと（ローカル）
- 使える拡張機能は `pg_trgm` と `pgroonga`。`pg_bigm` は選べない。
- `pg_trgm` は日本語の文字列も 3 文字ずつに区切れる（`show_trgm('アリーナ席')` が 6 個の断片を返した）。確認のために入れた拡張機能は消した。

### 書いたもの
- マイグレーションはなし。
- `CONTEXT.md`：「ファンサ」の項目に、会場ごとの平均は出さないことを追記した。

### 申し送り
- バックエンドのマップへ：検索と集計の SQL は Go に置く。表記の揺れをそろえる処理（`kana` との比較用のひらがな化、`name` との比較用の NFKC と小文字化。アイドルの一意インデックスは `lower(normalize(name, NFKC))`）。ファンサの平均は、アイドルや公演名で絞ったときだけ出す。遅くなったら `EXPLAIN` で確かめ、`pg_trgm` の GIN インデックスを足す（3 文字以上の検索語にしか効かないことに注意）。
- UI/UX のマップへ：件数が少ないときに平均を隠すかどうか（しきい値）。ファンサの会場平均は正確さには欠けるが、目を引く「フック」として面白いかもしれない、というアイデアがあった（今回は出さないことにした）。
